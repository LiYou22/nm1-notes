\section{Flops Are Not the Whole Story}

In \Cref{ch:fp} we asked whether we compute the \emph{right} answer. Now we ask how \emph{fast} we compute it. The surprise is that speed has little to do with the number of arithmetic operations.

\paragraph{Algorithms and computational cost.} Consider the algorithm for matrix multiplication
\begin{equation}
  A \mathrel{+}= BC, \qquad A \in \R^{\ell \times n},\ B \in \R^{\ell \times m},\ C \in \R^{m \times n}:
\end{equation}
\begin{lstlisting}
function matmuladd!(A, B, C)          # A += B*C
    for i = 1:l
        for j = 1:m
            for k = 1:n
                A[i,k] += B[i,j] * C[j,k]
            end
        end
    end
end
\end{lstlisting}
The innermost line runs $\ell \times m \times n$ times, so the computational cost is $\ell \times m \times n$. We set $\ell = 2 \cdot 10^4$, $m = 3 \cdot 10^4$ and time it with \texttt{@btime}:
\begin{center}
\begin{tabular}{ccc}
  \toprule
  $n$ & Cost $\ell mn$ & Time \\
  \midrule
  $1$ & $6 \cdot 10^8$ & $6 \cdot 10^{-2}$ s \\
  $10^3$ & $6 \cdot 10^{11}$ & $4$ s \\
  \bottomrule
\end{tabular}
\end{center}
The cost grows by a factor of $1000$, so we would expect $1000 \times 0.06\text{ s} = 60$ s. It takes only $4$ s: \emph{more than $10$ times faster than expected}.

\paragraph{Flops and memory access.} Does Julia use fewer operations? No: for $\ell = m = n$, the time grows roughly like the cost,
\begin{center}
\begin{tabular}{ccc}
  \toprule
  $\ell = m = n$ & Cost $\ell mn$ & Time \\
  \midrule
  $10^3$ & $10^9$ & $7 \cdot 10^{-3}$ s \\
  $10^4$ & $10^{12}$ & $6$ s \\
  \bottomrule
\end{tabular}
\end{center}
that is, about $1000$ times the cost in about $1000$ times the time. The explanation is that four operations appear in the algorithm: additions, multiplications, and reading and writing entries of the arrays (both written $[\ ]$). Their costs are very different:
\begin{equation}
  \operatorname{cost}(+) < \operatorname{cost}(\ast) \ll \operatorname{cost}([\ ]).
\end{equation}
\emph{Memory access is much slower than flops on modern hardware.}
\begin{itemize}
  \item For $n = 1$, every entry of $B$ is read and then used only once, so almost all of the time goes into memory access.
  \item For $n = 10^3$, every entry of $B$ is used $10^3$ times, so the cost of reading it is shared by many operations.
\end{itemize}

\section{Memory Is One-Dimensional}

Memory is a long string of bits, and a vector is a contiguous run of floating-point numbers $u_1, u_2, u_3, \dots$. There is no such thing as a two-dimensional matrix in memory; it must be flattened in some order. Julia, Fortran, BLAS, and LAPACK use \emph{column-major} order, storing entire columns contiguously:
\begin{equation}
  A_{11},\ A_{21},\ A_{31},\ A_{41},\ A_{12},\ A_{22},\ A_{32},\ A_{42},\ \dots
\end{equation}
so that $A_{ij}$ sits at linear index $i + (j - 1)m$. C and NumPy default to row-major order. Besides the data, one also stores metadata such as sizes, strides, and preallocated buffers.

Since the storage is just a contiguous block, the same memory can be \emph{reinterpreted} as an array of shape $m \times n \times k \times l$, $mn \times kl$, or $mnk \times l$ without any copying. Reshaping is free; transposing is not.

\section{The Memory Hierarchy}

Main memory is much slower than arithmetic, so hardware adds \emph{caches}: small, fast memory close to the processor. Two bottlenecks remain:
\begin{itemize}
  \item \emph{Latency}: how long one access waits (a few cycles for L1, a few hundred for main memory).
  \item \emph{Bandwidth}: how many bytes can be moved per second.
\end{itemize}
Latency is hidden by \emph{prefetching}: the hardware fetches nearby memory, or memory in a strided pattern, before it is needed. This only works for regular access patterns, so the \emph{regularity} of memory access often matters more than its volume. GPUs have no prefetching. Instead, many threads carry out the same instruction at once; if they access contiguous elements, the hardware combines their accesses into a single one, and otherwise the access is much slower. So on a GPU, non-contiguous access is very slow.

\section{Loop Reordering}

\begin{example}[Two Loop Orders for a Matrix--Vector Product]
  Both loops compute $\vec{u} = A\vec{v}$ with the same number of operations.
\begin{lstlisting}
# i outer: inner loop along a row of A       # j outer: inner loop down a column
for i = 1:m                                    for j = 1:n
    for j = 1:n                                    for i = 1:m
        u[i] += A[i,j] * v[j]                          u[i] += A[i,j] * v[j]
    end                                            end
end                                            end
\end{lstlisting}
  In column-major storage, the left loop walks along a row of $A$ (steps of $m$) and has at least two random accesses per step; the right loop walks down a column (contiguous) and has only one.
\end{example}

The left loop computes inner products of the rows of $A$ with $\vec{v}$ (\texttt{dot}); the right loop adds up the columns of $A$ times $v_j$ (\texttt{axpy}). Julia stores matrices by columns, so the right loop is faster. This matters most for \emph{small} matrices; for large ones, both loops spend most of their time waiting for main memory.

\section{Tiling}
\label{sec:tiling}

Even without cache misses, the limited bandwidth slows us down. The key observation: multiplying two $m \times m$ matrices takes about $m^3$ operations but involves only about $m^2$ numbers, so each number is used about $m$ times.
\begin{itemize}
  \item If all $m^2$ numbers fit into the cache, we load each of them from main memory only once, and then do all $m^3$ operations in the fast cache.
  \item If the matrices are too large, we \emph{tile}: split $A$, $B$, $C$ into $b \times b$ blocks, $N = m/b$ along each side, and multiply block by block. (For simplicity, assume $b$ divides $m$; otherwise the blocks at the edges are smaller.) We choose $b$ so that the three blocks we are working on fit into the cache; \Cref{sec:intensity} quantifies the gain.
\end{itemize}

Written out entry by entry, the tiled algorithm has \emph{six} nested loops: the outer three choose the blocks ($I, J, K$ count blocks, not entries), and the inner three multiply them.
\begin{lstlisting}
for I = 1:N, J = 1:N, K = 1:N              # which blocks: C_IJ += A_IK * B_KJ
    for i = (I-1)*b+1 : I*b                # multiply the two b x b blocks
        for j = (J-1)*b+1 : J*b
            for k = (K-1)*b+1 : K*b
                C[i,j] += A[i,k] * B[k,j]
            end
        end
    end
end
\end{lstlisting}
We do the same $m^3$ operations as before, just in a different order. The inner three loops only use three blocks, $3b^2$ numbers in total. These numbers stay in the cache, and each one is used about $b$ times before we move on to the next blocks.

\section{Linear Systems}

\paragraph{Problem.} Given $A \in \K^{m \times n}$ and $\vec{b} \in \range(A) \subseteq \K^m$, find $\vec{x} \in \K^n$ with
\begin{equation}
  A\vec{x} = \vec{b}.
\end{equation}
The condition $\vec{b} \in \range(A)$ just says that a solution exists.
\begin{itemize}
  \item Linear systems appear in virtually all of mathematics.
  \item They \emph{can} be solved by computing $A^{-1}$, but they \emph{need not} be. Computing $A^{-1}$ is in fact the wrong way: it costs more ($2m^3$ flops for a square matrix, versus $\tfrac{2}{3}m^3$ for the LU factorization of \Cref{ch:lu}), and it usually gives a less accurate answer.
\end{itemize}

\paragraph{Square matrices.} We begin with $A \in \K^{m \times m}$. Then the following three conditions are equivalent:
\begin{equation}
  \underbrace{\nullsp(A) = \{\zerovec\}}_{\vec{x} \mapsto A\vec{x} \text{ injective}}
  \iff \text{the columns of } A \text{ are linearly independent} \iff
  \underbrace{\range(A) = \K^m}_{\vec{x} \mapsto A\vec{x} \text{ surjective}}
\end{equation}
In words:
\begin{itemize}
  \item \emph{Left}: only $\vec{x} = \zerovec$ is mapped to $\zerovec$. Then different inputs give different outputs: if $A\vec{x} = A\vec{y}$, then $A(\vec{x} - \vec{y}) = \zerovec$, so $\vec{x} = \vec{y}$. Hence a solution, if it exists, is unique.
  \item \emph{Right}: every $\vec{b} \in \K^m$ is of the form $A\vec{x}$. Hence a solution always exists.
\end{itemize}
If these conditions hold, we say that \emph{$A$ has full rank}, \emph{is invertible}, or \emph{is nonsingular}; then $A\vec{x} = \vec{b}$ has exactly one solution for every $\vec{b}$. For rectangular matrices, injective and surjective are no longer the same; they are treated in \Cref{ch:ls}.

\section{Triangular Systems}

We begin with the easy case. The small example
\begin{equation}
  \begin{aligned} x_1 + 5 &= 15 \\ x_1 + 5x_2 &= 20 \end{aligned} \qquad\Longrightarrow\qquad x_1 = 10,\ x_2 = 2
\end{equation}
already shows the whole idea: $x_1$ does not depend on $x_2$, so the triangular structure \emph{decouples} the unknowns and they can be solved for one at a time. For lower triangular $A$, \emph{forward substitution} computes
\begin{equation}
  x_1 = \frac{b_1}{A_{11}}, \qquad x_i = \frac{1}{A_{ii}}\left(b_i - \sum_{j=1}^{i-1} A_{ij}x_j\right), \quad i = 2, \dots, m.
\end{equation}
Upper triangular systems are solved in reverse order by \emph{back substitution}. The same formula admits two implementations, both costing $\sim m^2$ flops but with different access patterns.

\begin{algorithm}[H]
  \caption{Forward substitution, row-oriented (\texttt{dot} form).}
  \begin{algorithmic}[1]
    \For{$i = 1, \dots, m$}
      \State $x_i \gets b_i$
      \For{$j = 1, \dots, i - 1$}
        \State $x_i \gets x_i - A_{ij}x_j$
      \EndFor
      \State $x_i \gets x_i / A_{ii}$
    \EndFor
  \end{algorithmic}
\end{algorithm}

\begin{algorithm}[H]
  \caption{Forward substitution, column-oriented (\texttt{axpy} form), the efficient variant.}
  \begin{algorithmic}[1]
    \State $\vec{x} \gets \vec{b}$
    \For{$j = 1, \dots, m$}
      \State $x_j \gets x_j / A_{jj}$
      \For{$i = j + 1, \dots, m$}
        \State $x_i \gets x_i - A_{ij}x_j$ \Comment{remove the contribution of $x_j$ at once}
      \EndFor
    \EndFor
  \end{algorithmic}
\end{algorithm}

For upper triangular $A$, $x_m$ is the only unknown in the last equation, so back substitution starts from the bottom:
\begin{equation}
  x_m = \frac{b_m}{A_{mm}}, \qquad x_i = \frac{1}{A_{ii}}\left(b_i - \sum_{j=i+1}^{m} A_{ij}x_j\right), \quad i = m - 1, \dots, 1.
\end{equation}
The two implementations mirror those of forward substitution, with every loop over the unknowns reversed.

\begin{algorithm}[H]
  \caption{Back substitution, row-oriented (\texttt{dot} form).}
  \begin{algorithmic}[1]
    \For{$i = m, \dots, 1$}
      \State $x_i \gets b_i$
      \For{$j = i + 1, \dots, m$}
        \State $x_i \gets x_i - A_{ij}x_j$
      \EndFor
      \State $x_i \gets x_i / A_{ii}$
    \EndFor
  \end{algorithmic}
\end{algorithm}

\begin{algorithm}[H]
  \caption{Back substitution, column-oriented (\texttt{axpy} form).}
  \begin{algorithmic}[1]
    \State $\vec{x} \gets \vec{b}$
    \For{$j = m, \dots, 1$}
      \State $x_j \gets x_j / A_{jj}$
      \For{$i = 1, \dots, j - 1$}
        \State $x_i \gets x_i - A_{ij}x_j$ \Comment{remove the contribution of $x_j$ at once}
      \EndFor
    \EndFor
  \end{algorithmic}
\end{algorithm}

In column-major storage the row forms walk along rows (strided) and the column forms walk down columns (contiguous); this is the matrix--vector discussion again.

\section{Gaussian Elimination}

A general matrix is not triangular. Gaussian elimination \emph{transforms $A$ into upper triangular form by a sequence of row operations}, reducing the general problem to a triangular one. A $2 \times 2$ example:
\begin{equation}
  \begin{aligned} x_1 + 2x_2 &= 10 \\ 2x_1 + x_2 &= 8 \end{aligned}
  \quad \xrightarrow{\ \text{row 2} \,-\, 2 \times \text{row 1}\ } \quad
  \begin{aligned} x_1 + 2x_2 &= 10 \\ -3x_2 &= -12 \end{aligned}
\end{equation}
In matrix language, this elimination step is a \emph{left multiplication}:
\begin{equation}
  \begin{bmatrix} 1 & 0 \\ -2 & 1 \end{bmatrix}
  \begin{bmatrix} 1 & 2 \\ 2 & 1 \end{bmatrix}
  \begin{bmatrix} x_1 \\ x_2 \end{bmatrix}
  =
  \begin{bmatrix} 1 & 0 \\ -2 & 1 \end{bmatrix}
  \begin{bmatrix} 10 \\ 8 \end{bmatrix}.
\end{equation}

\begin{theorem}[Elementary Lower Triangular Matrices]
  \label{thm:elim}
  Let $A \in \K^{m \times m}$ and suppose the first $k - 1$ columns of $A$ are already zero below the diagonal, and $A_{kk} \ne 0$. Define the multipliers $\ell_{ik} \defeq A_{ik}/A_{kk}$ for $i = k + 1, \dots, m$, the vector
  \begin{equation}
    \vec{\ell}_k \defeq \begin{bmatrix} 0 & \cdots & 0 & \ell_{k+1,k} & \cdots & \ell_{mk} \end{bmatrix}^\T,
  \end{equation}
  whose first $k$ entries vanish, and the \emph{elementary lower triangular matrix}
  \begin{equation}
    L_k \defeq I - \vec{\ell}_k \vec{e}_k^{\,\ast} =
    \begin{bmatrix}
      1 & & & & & \\
      & \ddots & & & & \\
      & & 1 & & & \\
      & & -\ell_{k+1,k} & 1 & & \\
      & & \vdots & & \ddots & \\
      & & -\ell_{mk} & & & 1
    \end{bmatrix}
    \begin{matrix} \\ \\ \leftarrow \text{row } k \\ \\ \\ \\ \end{matrix}
  \end{equation}
  Then $L_k A$ is zero below the diagonal in its first $k$ columns. Its first $k$ rows equal those of $A$, and only the trailing $(m - k) \times (m - k)$ block is updated.
\end{theorem}

\begin{proof}
  Left multiplication by $L_k$ performs, for each $i > k$, the row operation ``row $i$ minus $\ell_{ik}$ times row $k$''. The $(i, k)$ entry becomes $A_{ik} - \ell_{ik}A_{kk} = 0$. Row $k$ is zero in its first $k - 1$ columns, so the columns that have already been eliminated are not disturbed.
\end{proof}

Applying \Cref{thm:elim} for $k = 1, \dots, m - 1$ (assuming that each $A_{kk}$ is nonzero when we reach it) to both sides of $A\vec{x} = \vec{b}$ gives
\begin{equation}
  \underbrace{L_{m-1} \cdots L_1 A}_{\text{upper triangular}}\,\vec{x} = L_{m-1} \cdots L_1 \vec{b}.
\end{equation}
With $U \defeq L_{m-1} \cdots L_1 A$ and $L \defeq (L_{m-1} \cdots L_1)^{-1}$, we obtain $A = LU$ with $U$ upper triangular. We stop here with two questions: \emph{is $L$ lower triangular, and can we compute it?} Both are answered in \Cref{ch:lu}.

\subsection{Leading Dimension}

In column-major order, the entry $A_{ij}$ lives at
\begin{equation}
  \operatorname{addr}(A_{ij}) = \text{base} + (j - 1) \cdot \mathrm{lda} + (i - 1),
\end{equation}
where the \emph{leading dimension} $\mathrm{lda} \ge m$ is the distance between consecutive columns. Allowing $\mathrm{lda} \ne m$ lets us describe a \emph{submatrix} of a larger matrix by the quadruple (start address, $m$, $n$, $\mathrm{lda}$) without copying any data. This is what Julia's \texttt{view} and \texttt{@views} do, whereas \texttt{A[1:100, 1:100]} makes a copy.

\subsection{Computational Intensity}
\label{sec:intensity}

The discussion of this lecture can be quantified~\cite[\S2.6]{Demmel}. Consider two levels of memory, a fast memory of size $M$ and a slow memory. Let one flop take time $t_f$ and one slow-memory access take time $t_m \gg t_f$.

\begin{definition}[Computational Intensity]
  If an algorithm performs $f$ flops and $m$ slow-memory accesses, its \emph{computational intensity} is $q \defeq f/m$.
\end{definition}

The total time is roughly
\begin{equation}
  T = f t_f + m t_m = f t_f \left(1 + \frac{t_m}{t_f} \cdot \frac{1}{q}\right).
\end{equation}
Running near the peak rate $f t_f$ requires $q \gg t_m / t_f$, and on modern machines $t_m / t_f$ is in the tens to hundreds. The three levels of the BLAS are distinguished precisely by $q$ (here $n$ is the vector length or matrix order):
\begin{center}
\begin{tabular}{lllll}
  \toprule
  Level & Typical operation & Flops $f$ & Accesses $m$ & $q$ \\
  \midrule
  Level 1 & \texttt{axpy} $\vec{y} \gets \alpha\vec{x} + \vec{y}$, \texttt{dot} & $2n$ & $3n$ & $2/3$ \\
  Level 2 & \texttt{gemv} $\vec{y} \gets \alpha A\vec{x} + \beta\vec{y}$, triangular solve & $2n^2$ & $n^2$ & $2$ \\
  Level 3 & \texttt{gemm} $C \gets \alpha AB + \beta C$ & $2n^3$ & $4n^2$ & $n/2$ \\
  \bottomrule
\end{tabular}
\end{center}
Only Level 3 has an intensity that grows with the problem size, matching the observation that matrix multiplication performs $m^3$ flops on $m^2$ data. Triangular solves, in either loop order, are Level 2 with $q \approx 2$ and are fundamentally limited by bandwidth.

For naive matrix multiplication $C \mathrel{+}= AB$ with three $n \times n$ matrices, the innermost loop scans a whole column of $B$ each time. Then $A$ is read once ($n^2$), $C$ is read and written once ($2n^2$), and $B$ is read $n$ times ($n^3$), so
\begin{equation}
  q = \frac{2n^3}{n^3 + 3n^2} \approx 2,
\end{equation}
no better than Level 2. For the tiled version (\Cref{sec:tiling}) the slow-memory traffic is $m = 2n^2 + 2Nn^2$, so
\begin{equation}
  q \approx \frac{2n^3}{2Nn^2} = \frac{n}{N} = b.
\end{equation}
The intensity equals the block size. Three blocks must reside in fast memory simultaneously, so $3b^2 \le M$, i.e., $b \le \sqrt{M/3}$, and hence $q \approx \sqrt{M/3}$. A lower bound of Hong and Kung shows that any matrix multiplication that only reorders the sums has $q = O(\sqrt{M})$, so tiling is asymptotically optimal. Real implementations tile at \emph{several} levels (registers, L1, L2, and across nodes), each with its own $b$.

\subsection{Blocked LU}
\label{sec:blocked-lu}

The in-place LU algorithm of \Cref{ch:lu} spends its time in rank-one updates, a Level 2 operation with $q \approx 2$, so naive Gaussian elimination is bandwidth-bound. The tiling idea fixes this~\cite[\S2.6.3]{Demmel}. Choose a block width $b$ and write
\begin{equation}
  A = \begin{bmatrix} A_{11} & A_{12} \\ A_{21} & A_{22} \end{bmatrix}, \qquad A_{11} \in \K^{b \times b}.
\end{equation}
\begin{enumerate}
  \item Factor the $m \times b$ panel $\begin{bmatrix} A_{11} \\ A_{21} \end{bmatrix}$ by ordinary elimination, obtaining $L_{11}$, $L_{21}$, $U_{11}$. This is still Level 2, but it accounts for only an $O(b/m)$ fraction of the work.
  \item Compute $U_{12} = L_{11}^{-1}A_{12}$, a triangular solve with many right-hand sides (Level 3).
  \item Compute $\tilde{A}_{22} = A_{22} - L_{21}U_{12}$, a matrix multiplication (Level 3) that contains most of the flops.
  \item Recurse on $\tilde{A}_{22}$.
\end{enumerate}
Only an $O(b/m)$ fraction of the $\tfrac{2}{3}m^3$ flops remains in bandwidth-bound Level 2 operations; the rest runs as matrix multiplication and enjoys $q \approx b$. This is where LAPACK's \texttt{getrf} gains its large speedup over the older LINPACK, and it is the first real instance of the rule ``rewrite everything as matrix multiplication''.
